# Borrow — 로컬 팝업/이벤트 AI 기획 및 유동인구 매칭 플랫폼

해커톤 프로젝트. 아래 내용은 초기 템플릿이며, 실제 구현이 진행되면서 구체적인 디렉토리 구조/컨벤션/명령어로 계속 채워나갈 것.

## 한 줄 컨셉

카페, 식당, 술집 등 **원래 다른 용도로 쓰이는 공간의 유휴시간**을 예술인 클래스 공간으로 재활용한다.

## 문제 정의 (지역 문제로서)

- 대전/충남은 대학이 많은데 대학가 상권은 종강 시즌에 유동인구·매출이 확 줄어듦 (성심당·야구장 말고는 유동인구 유인 요소가 부족)
- 종강 시즌엔 공간도 비고 손님도 없음 → 그럴 바엔 그 유휴 시간을 다른 용도(클래스)로라도 활용하자는 것
- 공간을 갖고 있지 않은 예술인(클래스를 열고 싶은 사람) 입장에서는 저렴하게 시간제로 빌릴 수 있는 대안이 됨

## spacecloud와의 차별화 (핵심 포지셔닝)

- spacecloud 등 기존 공간대여 플랫폼은 **대여 자체가 목적인 전용 공간**을 빌려주는 서비스
- 우리는 **다른 용도로 운영되다가 비는 시간**만 빌려주는 것 — 카페/식당/술집의 유휴시간 재활용이 핵심 차별점. 발표 시 가장 앞에 내세울 포지셔닝.

## 핵심 사용자 (역할 3종 / 클라이언트 2종)

- **제공자(사장) 클라이언트**: 카페/식당/술집 등 공간을 소유하고 비는 시간이 있는 사람. 공간 조건(업종, 평수, 비는 시간대) 입력 → AI가 맞춤 클래스 기획 가이드라인 + 매칭 점수 생성
- **소비자 — 예술인(클래스 제공)**: 공간을 갖고 있지 않지만 클래스를 열고 싶은 사람. 원하는 시간·공간 검색 후 선택, 클래스 등록
- **소비자 — 일반인(클래스 수강)**: 별도 앱 대신 예술인 클라이언트 안에 클래스 탐색·신청 뷰(리스트+지도)로 흡수 — 해커톤 기간 내 3앱 유지는 비효율적이라 판단

## 비즈니스 모델

- **제공자**: 구독 형식 — 특정 기간 동안 자신의 유휴시간을 대여 가능하도록 등록 (MVP 데모에서는 건별 예약으로 단순화하고 구독은 로드맵으로 소개 권장)
- **소비자(예술인/일반인)**: 원하는 시간·원하는 공간을 검색 후 선택하는 방식

## 운영 이슈: 공간 청소

- 사용 후 청소를 스스로 하면 크레딧 지급 (쏘카 세차 크레딧 방식)
- 또는 청소 전담 인력을 매칭/고용 (전동킥보드 충전 매칭 구조와 유사)

## MVP 범위

- **필수**: 공간 조건 입력 → AI가 클래스 기획 가이드라인 + 매칭 점수 출력 (핵심 기능 1개)
- **보조**: 클래스 등록 폼, 지역 공간 지도 뷰, 클래스 탐색/신청 리스트

## 기술 스택 & 아키텍처

- **Expo** (React Native) — 사장/학생 클라이언트 공통. Spring 백엔드 한 곳만 호출.
- **Spring** — 메인 백엔드. 인증, CRUD, 매칭 로직, DB 소유.
- **FastAPI** — AI 전용 마이크로서비스. LLM 프롬프트 생성/스코어링 담당. Spring이 내부적으로 호출 (Expo가 직접 호출하지 않음).

```
Expo (사장 앱 / 학생 앱)
   └── Spring (인증, CRUD, 매칭 로직, DB)
           └── FastAPI (AI: 이벤트 가이드라인 생성, 매칭 스코어링)
```

> 인증 토큰 이원화, CORS 이중 설정을 피하기 위해 Expo는 반드시 Spring만 바라본다.
